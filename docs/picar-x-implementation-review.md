# PiCar-X Implementation Review

Reverse-engineering analysis of the SunFounder PiCar-X robot kit, its Robot HAT expansion board, Python software stack, and porting considerations for GoRAI.

---

## 1. Hardware Architecture

### 1.1 System Overview

The PiCar-X is a four-wheeled (two driven, two passive/caster) robot car platform built around:

- **Host computer:** Raspberry Pi 3B+, 4, or newer (Pi 5 NOT supported by Robot HAT V4)
- **Expansion board:** SunFounder Robot HAT V4 (sits on the Pi 40-pin header)
- **Actuators:** 2 DC motors (rear differential drive), 3 servos (steering, camera pan, camera tilt)
- **Sensors:** HC-SR04 ultrasonic, 3-channel grayscale line sensor, 5MP camera (OV5647)
- **Audio:** I2S mono speaker with MAX98357-compatible amplifier

### 1.2 Robot HAT V4 Board

The Robot HAT V4 is the critical hardware interface. It contains:

| Component | Details |
|-----------|---------|
| **On-board MCU** | ARM Cortex-M class MCU running at 72 MHz clock. Likely an STM32F0xx or GD32-series chip (the Fusion HAT+ successor uses GD32; exact V4 model not documented publicly). I2C slave address **0x14** (fallback 0x15). |
| **Motor driver** | 2-channel H-bridge driver (TB6612FNG-class), supports 2 DC motors with direction + PWM speed control |
| **PWM outputs** | 12 servo-compatible PWM outputs (P0-P11) + 2 motor PWM outputs (P12-P13), all generated by the on-board MCU |
| **ADC inputs** | 4 analog channels (A0-A3), 12-bit resolution (0-4095), exposed via I2C registers |
| **Digital I/O** | 17 digital pins (D0-D16) directly mapped to Raspberry Pi BCM GPIO |
| **I2C interfaces** | 2x I2C connectors (P2.54 4-pin + SH1.0 4-pin QWIIC/STEMMA QT compatible) on GPIO2 (SDA) / GPIO3 (SCL) |
| **SPI interface** | 7-pin P2.54 header connected to Pi SPI bus |
| **UART** | Connected to Pi GPIO14 (TXD) / GPIO15 (RXD) |
| **Audio** | I2S digital audio (MAX98357-compatible DAC/amplifier) with mono speaker |
| **Power** | 6.0-8.4V input via 3-pin XH2.54, USB-C charging, battery status LEDs |
| **User I/O** | 1 LED (GPIO26), 2 buttons (SW/USER pin) |
| **MCU reset** | MCURST pin for hardware reset of the on-board MCU |

### 1.3 On-Board MCU I2C Register Map

The MCU at address 0x14 provides PWM generation and ADC reading via I2C registers. Communication uses the SMBus protocol over Linux `/dev/i2c-1`.

#### Register Address Scheme

| Register Base | Purpose | Value Range | Notes |
|--------------|---------|-------------|-------|
| **0x10-0x13** | ADC channels 0-3 | Read: 12-bit (0-4095) | Channel encoding: `(7 - channel) \| 0x10` |
| **0x20 + channel** | PWM pulse width (duty) | 0-65535 (16-bit) | Per-channel duty cycle in timer counts |
| **0x30 + channel** | PWM frequency config | See below | Per-channel frequency register |
| **0x40 + timer** | PWM prescaler | 0-65535 | Stored as prescaler-1 |
| **0x44 + timer** | PWM period (ARR) | 0-65535 | Auto-reload register value |

#### PWM Timer Architecture

The MCU has **4 hardware timers** shared across 14 PWM channels:

| Timer | Channels | Typical Use |
|-------|----------|-------------|
| Timer 0 | P0, P1, P2, P3 | Servos (50 Hz) |
| Timer 1 | P4, P5, P6, P7 | Servos (50 Hz) |
| Timer 2 | P8, P9, P10, P11 | Servos (50 Hz) |
| Timer 3 | P12, P13 | Motors (variable freq) |

**Constraint:** All channels sharing a timer MUST use the same frequency. Changing the prescaler or period on one channel affects all channels on that timer.

#### PWM Frequency Calculation

```
frequency = clock / (prescaler * period)
         = 72,000,000 / (prescaler * period)
```

For 50 Hz servo control with period=4095:
```
prescaler = 72,000,000 / (50 * 4095) = 351.6 -> 352
actual_freq = 72,000,000 / (352 * 4095) = 49.93 Hz
```

The Python code uses a square-root approximation to find optimal prescaler/period pairs that minimize frequency error:

```python
# From robot_hat/pwm.py
def freq(self, freq):
    # Calculate optimal prescaler and period
    result_ap = []
    result_acy = []
    st = int(math.sqrt(self.CLOCK / freq))
    for psc in range(st - 5, st + 5, 1):
        if psc < 1: continue
        arr = int(self.CLOCK / freq / psc)
        result_ap.append([psc, arr])
        result_acy.append(abs(freq - self.CLOCK / psc / arr))
    # Select pair with minimum error
    best = result_acy.index(min(result_acy))
    psc, arr = result_ap[best]
    self.prescaler(psc)
    self.period(arr)
```

#### ADC Read Protocol

Reading an ADC channel requires a write-then-read I2C transaction:

```python
# From robot_hat/adc.py
# Channel address calculation:
chn = 7 - chn        # Invert channel number
chn = chn | 0x10     # Set bit 4 (result: 0x17 for A0, 0x16 for A1, etc.)

# Read sequence:
# 1. Write channel address byte to device 0x14
self._i2c_write_byte_data(0x14, chn, 0)
# 2. Read 2 bytes (MSB, LSB)
value_h = self._i2c_read_byte(0x14)
value_l = self._i2c_read_byte(0x14)
# 3. Combine
value = (value_h << 8) + value_l  # 0-4095
```

ADC channel to register mapping:

| Channel | Register Address |
|---------|-----------------|
| A0 | 0x17 |
| A1 | 0x16 |
| A2 | 0x15 |
| A3 | 0x14 |

#### PWM Write Protocol

Writing a PWM pulse width to a channel:

```python
# From robot_hat/pwm.py
def i2c_write(self, reg, value):
    value_h = value >> 8          # High byte
    value_l = value & 0xff        # Low byte
    self._i2c_write_i2c_block_data(0x14, reg, [value_h, value_l])

# Set pulse width on channel N:
i2c_write(REG_CHN + channel, pulse_value)  # REG_CHN = 0x20

# Set prescaler for timer:
i2c_write(REG_PSC + timer, prescaler - 1)  # REG_PSC = 0x40

# Set period for timer:
i2c_write(REG_ARR + timer, period)          # REG_ARR = 0x44
```

All 16-bit values are sent as 2 bytes, MSB first.

### 1.6 Servo Specifications

All three servos are standard analog RC servos controlled via PWM:

| Parameter | Value |
|-----------|-------|
| Control frequency | 50 Hz (20 ms period) |
| Minimum pulse width | 500 us |
| Maximum pulse width | 2500 us |
| Center pulse width | 1500 us |
| Angle range | -90 to +90 degrees |
| PWM period register value | 4095 |

Pulse width to angle mapping:
```
pulse_us = map(angle, -90, +90, 500, 2500)
pulse_fraction = pulse_us / 20000
pwm_value = int(pulse_fraction * 4095)
```

For example, 0 degrees (center):
```
pulse_us = 1500
pulse_fraction = 1500 / 20000 = 0.075
pwm_value = int(0.075 * 4095) = 307
```

### 1.7 Motor Control

DC motors use direction pins (GPIO) + PWM speed control:

| State | Direction Pin | PWM |
|-------|--------------|-----|
| Forward | LOW (0) | Speed % |
| Reverse | HIGH (1) | Speed % |
| Stop | Any | 0% |

Motor PWM configuration:
- Period: 4095 (register value)
- Prescaler: 10
- Effective frequency: 72,000,000 / (10 * 4095) = ~1758 Hz

Speed is specified as 0-100% and mapped to PWM duty cycle:
```python
if speed != 0:
    speed = int(speed / 2) + 50  # Maps 1-100 to 50-100 range
    speed = speed - cali_speed_value
```

This mapping means motor speed is never below ~50% duty cycle when active, providing a minimum torque threshold.

### 1.8 Sensors

#### HC-SR04 Ultrasonic Sensor

- Range: 2-400 cm
- Interface: GPIO trigger (output) + echo (input with pull-down)
- Protocol: Send 10us HIGH pulse on TRIG, measure HIGH duration on ECHO
- Distance calculation: `distance_cm = echo_duration_seconds * 340 / 2 * 100`
- Timeout: 20 ms (default)
- Retry: Up to 10 attempts per measurement

#### 3-Channel Grayscale Sensor

- 3 independent analog channels read via MCU ADC (A0, A1, A2)
- 12-bit resolution (0-4095)
- Higher values = lighter/more reflective surface
- Used for line following (reference ~1000) and cliff detection (reference ~500)
- Line position determined by comparing readings against configurable reference thresholds

#### Camera Module

- Sensor: OV5647 (5 megapixel)
- Interface: CSI (Camera Serial Interface) ribbon cable
- Resolution: Up to 2592x1944 (typically used at lower resolution for real-time processing)
- Mounted on 2-axis pan/tilt servo gimbal (P0=pan, P1=tilt)

## 2. Software Architecture

### 2.1 Language and Stack

The entire PiCar-X software stack is **Python 3**. There are two key packages:

1. **`robot_hat`** - Low-level hardware abstraction library (pip: `robot-hat`)
2. **`picarx`** - High-level robot control library built on `robot_hat`

Additional optional libraries:
- **`vilib`** - Vision library (OpenCV + TensorFlow Lite + MediaPipe + pyzbar)
- **`sunfounder_controller`** - Remote control server/client
- **`readchar`** - Keyboard input

### 2.3 I2C Communication Layer

The `I2C` class wraps Python's `smbus.SMBus` on bus 1 (`/dev/i2c-1`):

```python
class I2C(_Basic_class):
    MASTER = 0
    SLAVE = 1
    RETRY = 5

    def __init__(self, *args, **kargs):
        super().__init__()
        self._bus = SMBus(1)
```

All I2C operations use a `_retry_wrapper` decorator that retries failed operations up to 5 times, catching `OSError`. Key operations:

| Method | SMBus Call | Description |
|--------|-----------|-------------|
| `_i2c_write_byte(addr, data)` | `write_byte` | Write single byte |
| `_i2c_write_byte_data(addr, reg, data)` | `write_byte_data` | Write byte to register |
| `_i2c_write_i2c_block_data(addr, reg, data)` | `write_i2c_block_data` | Write byte array to register |
| `_i2c_read_byte(addr)` | `read_byte` | Read single byte |
| `_i2c_read_i2c_block_data(addr, reg, n)` | `read_i2c_block_data` | Read n bytes from register |

Higher-level methods (`send`, `recv`, `mem_write`, `mem_read`) add type conversion and flexible input handling.

### 2.4 PWM Control

The `PWM` class extends `I2C` to control individual PWM channels on the MCU:

```python
class PWM(I2C):
    REG_CHN = 0x20      # Pulse width register base
    REG_FRE = 0x30      # Frequency register base
    REG_PSC = 0x40      # Prescaler register base
    REG_ARR = 0x44      # Period (ARR) register base
    ADDR = 0x14         # MCU I2C address (fallback: 0x15)
    CLOCK = 72000000    # MCU clock: 72 MHz
```

Channel initialization:
```python
def __init__(self, channel, *args, **kwargs):
    # Channel specified as string "P0" through "P14"
    if isinstance(channel, str):
        # Parse "P0" -> channel 0
        if channel.startswith("P"):
            channel = int(channel[1:])
    # Validate channel 0-14
    self.channel = channel
    self.timer = int(channel / 4)  # 4 channels per timer
    self._freq = 50  # Default 50 Hz
    self.freq(50)
```

Writing a 16-bit value to an I2C register:
```python
def i2c_write(self, reg, value):
    value_h = value >> 8
    value_l = value & 0xff
    self._i2c_write_i2c_block_data(self.ADDR, reg, [value_h, value_l])
```

### 2.5 Servo Control

The `Servo` class wraps a `PWM` instance to provide angle-based positioning:

```python
class Servo(_Basic_class):
    MAX_PW = 2500   # Maximum pulse width (us)
    MIN_PW = 500    # Minimum pulse width (us)
    _freq = 50      # 50 Hz

    def __init__(self, pwm):
        self.pwm = pwm
        self.pwm.period(4095)
        prescaler = int(float(self.pwm.CLOCK) / self.pwm._freq / self.pwm.period())
        self.pwm.prescaler(prescaler)

    def angle(self, angle):
        if angle < -90: angle = -90
        if angle > 90: angle = 90
        High_level_time = self.map(angle, -90, 90, self.MIN_PW, self.MAX_PW)
        pwr = High_level_time / 20000   # Fraction of 20ms period
        value = int(pwr * self.pwm.period())  # Convert to timer counts
        self.pwm.pulse_width(value)
```

### 2.6 Motor Control

The `Motor` class uses 2 GPIO direction pins and 2 PWM speed pins:

```python
# PiCar-X motor pin assignments
left_rear_dir_pin = Pin("D4")       # GPIO 23
right_rear_dir_pin = Pin("D5")      # GPIO 24
left_rear_pwm_pin = PWM("P13")      # MCU PWM channel 13
right_rear_pwm_pin = PWM("P12")     # MCU PWM channel 12

# Motor PWM configuration
PERIOD = 4095
PRESCALER = 10

# Speed control with direction calibration
def set_motor_speed(self, motor, speed):
    speed = constrain(speed, -100, 100)
    motor -= 1  # 1-indexed to 0-indexed
    if speed >= 0:
        direction = 1 * self.cali_dir_value[motor]
    elif speed < 0:
        direction = -1 * self.cali_dir_value[motor]
    speed = abs(speed)
    if speed != 0:
        speed = int(speed / 2) + 50
        speed = speed - self.cali_speed_value[motor]
    if direction < 0:
        self.motor_direction_pins[motor].high()
        self.motor_speed_pins[motor].pulse_width_percent(speed)
    else:
        self.motor_direction_pins[motor].low()
        self.motor_speed_pins[motor].pulse_width_percent(speed)
```

### 2.7 Differential Steering

The PiCar-X uses Ackermann-like steering with a front servo and differential rear drive. When turning, the inner wheel slows proportionally to the steering angle:

```python
def forward(self, speed):
    current_angle = self.dir_current_angle
    if current_angle != 0:
        abs_current_angle = abs(current_angle)
        if abs_current_angle > self.DIR_MAX:
            abs_current_angle = self.DIR_MAX
        # Reduce inner wheel speed proportionally to steering angle
        power_scale = (100 - abs_current_angle) / 100.0
        if (current_angle / abs_current_angle) > 0:
            # Turning right: slow left motor
            self.set_motor_speed(1, speed * power_scale)
            self.set_motor_speed(2, -speed)
        else:
            # Turning left: slow right motor
            self.set_motor_speed(1, speed)
            self.set_motor_speed(2, -speed * power_scale)
    else:
        self.set_motor_speed(1, speed)
        self.set_motor_speed(2, -speed)
```

Note: Motor 2 (right) runs in the opposite direction (-speed) because the motors are physically mirrored.

Before any hardware interaction, the MCU must be reset:

```python

    mcu_reset.off()     # Pull reset LOW

    mcu_reset.on()      # Release reset HIGH
    time.sleep(0.01)    # Wait 10 ms for MCU startup
```

## 4. Protocol Details

### 4.1 Complete I2C Transaction Examples

#### Setting a Servo to 0 Degrees

```
Target: MCU at I2C address 0x14
Channel: P2 (steering servo)

1. Set period to 4095:
   WRITE [0x44, 0x0F, 0xFF]  (REG_ARR + timer0, high=0x0F, low=0xFF)

2. Set prescaler to 351:
   WRITE [0x40, 0x01, 0x5E]  (REG_PSC + timer0, high=0x01, low=0x5E)
   (prescaler stored as value-1, so 351 = 352-1)

3. Calculate pulse width for 0 degrees:
   pulse_us = map(0, -90, 90, 500, 2500) = 1500
   fraction = 1500 / 20000 = 0.075
   value = int(0.075 * 4095) = 307 (0x0133)

4. Write pulse width:
   WRITE [0x22, 0x01, 0x33]  (REG_CHN + 2, high=0x01, low=0x33)
```

#### Reading Grayscale Sensor A0

```
Target: MCU at I2C address 0x14
Channel: A0 -> register 0x17

1. Write channel register:
   WRITE_BYTE_DATA [addr=0x14, reg=0x17, data=0x00]

2. Read high byte:
   READ_BYTE [addr=0x14] -> value_h

3. Read low byte:
   READ_BYTE [addr=0x14] -> value_l

4. Combine:
   value = (value_h << 8) | value_l   (range: 0-4095)
```

#### Setting Motor Speed to 50% Forward (Left Motor)

```
Target: MCU at I2C address 0x14, GPIO 23

1. Set motor direction (forward):
   GPIO 23 (D4) -> LOW

2. Calculate PWM duty:
   input_speed = 50
   mapped_speed = int(50/2) + 50 = 75
   duty_percent = 75%
   duty_value = int(75/100 * 4095) = 3071 (0x0BFF)

3. Write PWM:
   WRITE [0x2D, 0x0B, 0xFF]  (REG_CHN + 13, high=0x0B, low=0xFF)
```

### 4.2 Ultrasonic Sensor Protocol

GPIO-based time-of-flight measurement:

```
1. TRIG pin (D2/GPIO27) -> HIGH for 10 microseconds
2. TRIG pin (D2/GPIO27) -> LOW
3. Wait for ECHO pin (D3/GPIO22) to go HIGH
4. Measure duration of ECHO HIGH pulse
5. distance_cm = duration_seconds * 340 / 2 * 100
   (speed of sound = 340 m/s, divide by 2 for round trip)
```

Implementation with timeout and retry:

```python
def _read(self):
    self.trig.low()
    time.sleep(0.01)
    self.trig.high()
    time.sleep(0.00001)  # 10 us pulse
    self.trig.low()

    # Wait for echo start
    timeout_start = time.time()
    while not self.echo.value():
        if time.time() - timeout_start > self.timeout:
            return -1

    # Measure echo duration
    echo_start = time.time()
    while self.echo.value():
        if time.time() - echo_start > self.timeout:
            return -1

    during = time.time() - echo_start
    return during * 340 / 2 * 100  # cm

def read(self, times=10):
    for _ in range(times):
        result = self._read()
        if result != -1:
            return result
    return -1
```

### 4.3 Grayscale Line Following Protocol

Three analog sensors return 12-bit values. The `Grayscale_Module` compares readings against reference thresholds:

```python
class Grayscale_Module:
    def __init__(self, pin0, pin1, pin2, reference=None):
        self.pins = (pin0, pin1, pin2)
        self._reference = reference or [1000, 1000, 1000]

    def read(self):
        return [pin.read() for pin in self.pins]

    def read_status(self):
        # Returns string like "011" where 1 = above reference (on line)
        data = self.read()
        state = ['0', '0', '0']
        for i in range(3):
            if data[i] > self._reference[i]:
                state[i] = '1'
        return ''.join(state)
```

Line status interpretation (3 sensors: left, center, right):

| Pattern | Meaning | Action |
|---------|---------|--------|
| `010` | Centered on line | Go straight |
| `100` | Line to the left | Turn left |
| `001` | Line to the right | Turn right |
| `110` | Line left of center | Turn left gently |
| `011` | Line right of center | Turn right gently |
| `000` | No line detected | Lost line |
| `111` | All sensors on line | Wide line or perpendicular |

#### 5.3.2 HC-SR04 Ultrasonic Driver (`driver/hcsr04`)

GPIO-based distance measurement requires precise timing:

```go

    trig gpio.Pin

    // Trigger pulse
    u.trig.Set(false)

    time.Sleep(10 * time.Microsecond)
    u.trig.Set(false)

    // ...
    return distanceCM, nil

```

**Challenge:** Linux GPIO timing is not as precise as bare-metal. The Python implementation works because the time scales (microseconds to milliseconds) are tolerable with OS jitter. Go's `time.Sleep` has similar precision. For production quality, consider using the kernel's GPIO event interface (`GPIOD_LINE_EVENT`) for edge detection rather than polling.

### 5.4 Porting Challenges

1. **MCU I2C Protocol:** The Robot HAT MCU uses a custom register protocol (not a standard chip like PCA9685). The driver must be written from scratch based on the register map documented above. The GoRAI `driver/i2c/linux` implementation already provides the needed I2C primitives.

2. **GPIO Timing for Ultrasonic:** The HC-SR04 requires microsecond-level timing. Go on Linux can handle this, but userspace GPIO access introduces jitter. Using `libgpiod` edge events (which GoRAI's gpiod driver wraps) is more reliable than polling.

3. **Board Version Detection:** The Robot HAT has two board revisions with different GPIO mappings. The driver must read the BOARD_TYPE pin (GPIO12) at initialization to select the correct pin dictionary.

4. **MCU Reset on Startup:** The MCU must be reset via the MCURST GPIO pin before any I2C communication. The reset sequence (pull low 1ms, release, wait 210ms) must happen before any PWM or ADC operations.

5. **Timer Shared Frequency:** All PWM channels sharing a timer must use the same frequency. The driver must track timer assignments and prevent conflicting frequency settings.

6. **Camera/Vision:** The `vilib` library wraps OpenCV, TensorFlow Lite, and MediaPipe. This requires CGo and should be a satellite repository (`gorai-driver-picarx-vision` or similar). GoRAI's existing V4L2 camera driver handles raw capture; vision processing would be a separate service.

7. **Audio:** I2S audio setup requires device tree overlay configuration. Not a Go concern directly, but the setup script needs to be part of the deployment procedure.

8. **Motor Speed Mapping:** The Python code maps speed 1-100 to 50-100% duty cycle. This non-linear mapping must be preserved for consistent behavior. The calibration direction values ([1, 1] or [-1, -1]) must also be handled.

- Robot HAT MCU I2C driver (PWM + ADC)
- Board version detection
- MCU reset sequence
- Unit tests with mock I2C bus

- PWM servo driver (channels P0-P11)
- DC motor driver (channels P12-P13 + GPIO direction)
- Calibration file reader/writer

**Phase 3: Sensors**
- ADC-based grayscale sensor driver
- HC-SR04 ultrasonic driver (GPIO timing)
- Line following and cliff detection logic

**Phase 4: Base Composition**
- Ackermann-differential base combining motors + steering servo
- Differential speed scaling based on steering angle

**Phase 5: Camera & Vision**
- V4L2 camera capture (existing GoRAI driver)
- Pan/tilt control coordinated with servos
- Vision processing as satellite repo (OpenCV via CGo)
